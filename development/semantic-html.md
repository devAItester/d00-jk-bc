# Semantic HTML

Семантика задаётся по смыслу документа, а не по тому, как элемент должен выглядеть. Сначала строится правильная HTML-структура, затем CSS придаёт ей нужное визуальное представление. Это ровно тот принцип, который Мурыч подчёркивает в разборе семантической вёрстки: выбор тега определяется содержанием и его связями, а не размером, цветом или положением элемента.

## 1. Структура страницы

Базовый шаблон сайта должен выражать крупные области документа непосредственно HTML-элементами:

- `header` — вводная часть сайта или конкретного раздела.
- `nav` — крупный блок навигационных ссылок.
- `main` — доминирующее содержимое документа; на странице должен быть не более одного видимого `main`.
- `article` — самостоятельная, законченная композиция, которую в принципе можно распространять или переиспользовать отдельно.
- `section` — тематическая секция документа, обычно с заголовком.
- `aside` — содержимое, связанное с окружающим материалом косвенно, но имеющее самостоятельный смысл.
- `footer` — нижняя часть ближайшего sectioning-контекста; на уровне `body` это футер всей страницы.

**Регламент:** WHATWG HTML Living Standard, §4.3 «Sections», в частности §4.3.2 `article`, §4.3.3 `section`, §4.3.4 `nav`, §4.3.5 `aside`, §4.3.8 `header`, §4.3.9 `footer`; для `main` — §4.4.14. [WHATWG HTML Standard — Sections (§4.3)](https://html.spec.whatwg.org/multipage/sections.html)

## 2. `section` не является заменой `div`

`section` используется только тогда, когда внутри документа действительно появляется самостоятельная тематическая секция, которую имеет смысл включить в outline документа.

Если контейнер нужен только для CSS, раскладки или удобства скрипта, используется `div`.

Это прямо следует из WHATWG §4.3.3: `section` — тематическая группировка, обычно с заголовком; спецификация отдельно говорит, что это **не generic container** и рекомендует `div`, когда семантического смысла у контейнера нет.

**Практическое правило:** сначала спросить «какой смысл у этого блока?», а не «какой тег удобнее стилизовать?».

**Источник:** WHATWG §4.3.3 «The `section` element». [WHATWG §4.3.3 — section](https://html.spec.whatwg.org/multipage/sections.html#the-section-element)

## 3. `article` — самостоятельная единица содержания

`article` подходит для материала, который имеет самостоятельный смысл: статья, запись, комментарий, карточка товара, пост или другой законченный объект.

В нашем шаблоне это особенно важно для будущего реального контента: если элемент можно мысленно вынести со страницы и он всё ещё остаётся осмысленным, `article` — кандидат на семантический контейнер.

Вложенные `article` допустимы, если внутренние элементы действительно являются связанными самостоятельными материалами.

**Источник:** WHATWG §4.3.2 «The `article` element». [WHATWG §4.3.2 — article](https://html.spec.whatwg.org/multipage/sections.html#the-article-element)

Мурыч показывает тот же принцип на карточках: визуальная карточка должна быть отражена в структуре документа соответствующим семантическим блоком, а не превращена в набор безымянных `div`.

## 4. `nav` — не любой набор ссылок

`nav` предназначен для **крупного блока навигации**. Не каждая группа ссылок требует `nav`.

В частности, WHATWG прямо отмечает, что короткого набора ссылок в футере обычно достаточно внутри самого `footer`; отдельный `nav` там не обязателен.

Наше трёхколоночное дерево — именно навигация по сайту, поэтому `nav` в шаблоне оправдан.

**Источник:** WHATWG §4.3.4 «The `nav` element», особенно абзац о major navigation blocks и ссылках в footer. [WHATWG §4.3.4 — nav](https://html.spec.whatwg.org/multipage/sections.html#the-nav-element)

## 5. `main` — только основное содержимое

`main` обозначает доминирующее содержимое документа, исключая повторяющиеся header, footer, navigation и боковые области.

WHATWG требует не более одного видимого `main` на документе. WAI-ARIA Authoring Practices дополнительно рекомендует один top-level main landmark.

Наш layout поэтому должен иметь один `main`, а навигацию и футер держать вне него.

**Источник:** WHATWG §4.4.14 «The `main` element». [WHATWG §4.4.14 — main](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element)  
**Accessibility:** W3C WAI-ARIA APG, «Main Landmark». [W3C APG — Main Landmark](https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/examples/main.html)

## 6. `aside` — дополнительное, а не просто «правая колонка»

`aside` определяется смыслом, а не расположением. Это содержимое, которое связано с окружающим материалом косвенно и может быть отделено от него без потери основного смысла.

Поэтому «правый блок» не должен автоматически становиться `aside`. Если это основной контент — он остаётся частью `main`; если это самостоятельная боковая информация — тогда `aside`.

**Источник:** WHATWG §4.3.5 «The `aside` element». [WHATWG §4.3.5 — aside](https://html.spec.whatwg.org/multipage/sections.html#the-aside-element)

## 7. `header` и `footer` определяются контекстом

`header` и `footer` не означают буквально «самое верхнее» и «самое нижнее» место страницы.

- `header` может быть связан со страницей или с конкретным `article`/sectioning-контекстом.
- `footer` относится к ближайшему sectioning content; если такого предка нет, он относится ко всему `body`.
- `footer` не создаёт новую секцию сам по себе.
- Футер может содержать авторство, связанные ссылки, copyright и другие данные, относящиеся к соответствующей секции.

В нашем layout глобальный `footer` находится непосредственно в `body`, поэтому он семантически является футером всего сайта.

**Источник:** WHATWG §4.3.8 и §4.3.9. [WHATWG §4.3.9 — footer](https://html.spec.whatwg.org/multipage/sections.html#the-footer-element)

W3C WAI отдельно отмечает, что глобальный `footer` создаёт landmark `contentinfo`, что позволяет assistive technology быстро переходить к информации внизу страницы. [W3C WAI — Page Regions](https://www.w3.org/WAI/tutorials/page-structure/regions/)

## 8. Заголовки: смысл важнее размера

`h1`–`h6` обозначают **уровень заголовка**, а не размер шрифта.

Поэтому нельзя выбирать `h2` потому, что по макету текст должен выглядеть крупнее, чем `h3`. Правильный алгоритм:

1. определить семантическую структуру;
2. выбрать правильный уровень заголовка;
3. только после этого CSS настроить любой нужный размер, вес, отступ и цвет.

Именно это Мурыч подчёркивает в разборе: семантика имеет приоритет, визуальное представление накладывается поверх неё.

**Источник:** WHATWG §4.3.6 «The `h1`–`h6` elements» и §4.3.11 «Headings and outlines». [WHATWG §4.3.6 — headings](https://html.spec.whatwg.org/multipage/sections.html#the-h1,-h2,-h3,-h4,-h5,-and-h6-elements)

## 9. Современное правило уровней заголовков

Здесь важно отделять старую практику от действующей спецификации.

Современный WHATWG HTML Standard:

- не требует ровно одного `h1` на странице;
- если в документе есть заголовки, хотя бы один заголовок должен иметь уровень 1;
- следующий заголовок не может перескочить более чем на один уровень вниз: после `h2` допустим `h1`, `h2` или `h3`, но не `h4`;
- визуальная вложенность секций сама по себе не определяет номер `h1`–`h6`.

Спецификация прямо приводит `h1` → `section` → `h3` как **non-conforming** пример и исправляет его на `h2`.

Это отличается от старого HTML5 outline algorithm и от старого «правила хорошего тона», которое Мурыч разбирает исторически. Для нового сайта ориентируемся на действующую спецификацию, а не на устаревший outline algorithm.

**Источник:** WHATWG §4.3.11 «Headings and outlines», особенно правила в абзацах о наличии level-1 heading и допустимом offset уровня. [WHATWG §4.3.11 — headings and outlines](https://html.spec.whatwg.org/multipage/sections.html#headings-and-outlines)

## 10. Один семантический HTML для всех представлений

CSS не должен заставлять нас менять HTML-смысл.

Если по дизайну `h3` должен выглядеть как `h2`, стили `h2` применяются к `h3`; сам элемент остаётся `h3`.

Если блок визуально расположен слева, справа или снизу, это не меняет его семантический тип. CSS отвечает за layout, HTML — за структуру и смысл.

Это один из ключевых практических выводов из разбора Мурыча: **сначала семантика, потом CSS**.

## 11. `div` — контейнер без собственной семантики

WHATWG определяет `div` как элемент без специального смысла и прямо рекомендует рассматривать его как элемент последнего выбора, когда никакой более подходящий семантический элемент не подходит.

Поэтому правило проекта:

> Если для блока существует точный семантический элемент — используем его. Если смыслового элемента нет и контейнер нужен только для группировки/стилей — используем `div`.

**Источник:** WHATWG §4.4.16 «The `div` element». [WHATWG §4.4.16 — div](https://html.spec.whatwg.org/multipage/grouping-content.html#the-div-element)

## 12. Accessibility — семантика должна быть видна машинам

Семантическая HTML-разметка нужна не только поисковым системам. Она позволяет assistive technology понимать структуру страницы и переходить между её landmark-регионами.

W3C рекомендует по возможности помещать весь воспринимаемый пользователем контент в семантически значимые landmarks. При этом не следует дублировать нативную HTML-семантику ненужными `role`: например, `<main>` уже создаёт main landmark, поэтому `role="main"` не требуется.

**Источники:**  
- W3C WAI Technique H101 — semantic HTML regions. [W3C WAI H101](https://www.w3.org/WAI/WCAG21/Techniques/html/H101)
- W3C APG — Landmark Regions. [W3C APG — Landmark Regions](https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/)

## 13. Правило для нашего шаблона

Текущий layout должен сохранять следующую семантическую структуру:

`body → header → nav → main → footer`

При этом:

- `header` содержит идентичность сайта;
- `nav` содержит дерево навигации;
- `main` содержит только содержимое текущей страницы;
- Markdown-заголовки внутри `main` формируют иерархию документа;
- `article` и `section` добавляются только там, где содержимое действительно имеет соответствующий смысл;
- `aside` добавляется только для дополнительного, косвенно связанного содержимого;
- `footer` находится вне `main` и относится ко всей странице;
- CSS никогда не используется как основание для выбора семантического элемента.

Это правило является базовым для дальнейшей верстки реального сайта.
