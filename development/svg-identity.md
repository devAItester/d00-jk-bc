# SVG identity

Для сайта используются два небольших SVG:

    assets/logo.svg
    assets/icon.svg

Суть графики намеренно нейтральна. Важны не рисунок и не брендовый сюжет, а техническое поведение.

## Logo

Logo — горизонтальный монохромный wordmark. Он используется в header вместо текстового элемента b.

Требования:

    - самостоятельный SVG-файл;
    - viewBox/размеры заданы явно;
    - цвет задаётся через currentColor;
    - есть title/desc;
    - нет растровых зависимостей;
    - нет JavaScript;
    - светлая и тёмная тема используют разные значения цвета.

## Icon

Icon — компактный знак для favicon. Он не пытается дублировать весь wordmark и должен оставаться различимым при малом размере.

Для favicon используется:

    <link rel="icon" href="/assets/icon.svg" type="image/svg+xml">

## Светлая и тёмная тема

Внутри SVG используется:

    :root { color: #000; }

    @media (prefers-color-scheme: dark) {
      :root { color: #fff; }
    }

Это не означает, что сайт содержит два разных файла. Один SVG выбирает вариант отображения по предпочтению цветовой схемы.

MDN отдельно документирует, что prefers-color-scheme может применяться внутри SVG, включая SVG, подключённый через img. citeturn3search0

Поэтому схема подходит для статического сайта без JavaScript.

## Доступность

SVG, используемый как содержательный графический объект, получает role=img и текстовый title. Для декоративных иконок внутри HTML, наоборот, предпочтительно использовать aria-hidden=true; W3C Design System прямо рекомендует такой паттерн для декоративных SVG. citeturn5search5

W3C SVG 2 определяет title и desc как descriptive elements и требует предоставлять их текстовое содержимое пользовательским агентам для accessibility API. citeturn5search1

## Почему отдельные SVG, а не inline

В этом проекте логотип и favicon не требуют взаимодействия. Отдельный файл:

    проще кешировать;
    проще проверять;
    не увеличивает HTML;
    не требует JavaScript;
    позволяет самому SVG реагировать на prefers-color-scheme.

Inline SVG понадобился бы, если бы цвет должен был наследоваться непосредственно из CSS страницы через currentColor или если графикой нужно управлять из DOM.

## Проверка

После изменения identity:

    1. открыть страницу в light mode;
    2. проверить logo и favicon;
    3. переключить OS/browser на dark mode;
    4. убедиться, что оба SVG инвертировали только цвет;
    5. проверить отсутствие растровых запросов;
    6. открыть SVG напрямую и убедиться, что он остаётся валидным XML/SVG.

Смысл решения:

    одна геометрия
        +
    один SVG-файл
        +
    prefers-color-scheme
        =
    два корректных визуальных варианта без JS.
